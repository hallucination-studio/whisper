# Cargo and Workspace

Read this file for manifests, workspace layout, features, dependencies, lint configuration, MSRV, or new crates.

- Respect the checked-in toolchain and MSRV. Update MSRV conservatively. New crates use the latest stable edition unless the workspace says otherwise; new library crates declare an intentional `rust-version` (M-LATEST-EDITION, M-MSRV).
- In a multi-crate workspace, centralize shared metadata, every dependency declaration (including crate-specific ones), profiles, and lints in root `Cargo.toml`; inherit them with `.workspace = true`. Prefer `default-features = false` in workspace dependency definitions and enable needed features per crate (M-CARGO-WORKSPACE).
- List and version all workspace crates at the root. Prefer sibling crate directories in one dedicated folder; do not place a real crate anywhere inside another crate's directory tree (M-CRATES-FLAT-FOLDER, M-CRATES-IN-WORKSPACE).
- Features are additive: enabling one may add API or behavior but cannot remove or modify an existing public item. Do not use a `no-std` feature; use `std` when opt-in is needed. Features automatically enable dependency features they require, and every combination of features that are individually supported on the current platform must work; do not evade this with mutual-exclusion errors (M-FEATURES-ADDITIVE).
- Libraries work by default on applicable Rust Tier-1 platforms without additional external prerequisites, tools, or environment variables. Gate platform-specific dependencies with `cfg` or opt-in features, and ship required generated artifacts (M-OOBE).
- Follow the Rust API Guidelines, Rust Style Guide, Rust Design Patterns, and Rust undefined-behavior references. Manifest work must preserve conventional feature naming (M-UPSTREAM-GUIDELINES).
- Native `-sys` crates build from a clean environment without network access or required global tools by default. Vendor verifiable source, prefer direct `cc` builds and pre-generated bindings, and make external tools optional. Any supported download path needs a stable source and integrity hash. Support static linking and, where the native library permits it, dynamic loading without introducing a mandatory system dependency (M-SYS-CRATES).
- Use compiler lints, Clippy, rustfmt, `cargo audit`, `cargo hack`, `cargo udeps`, and Miri as applicable. New lint configurations enable major Clippy categories plus key safety/quality lints such as `unsafe_op_in_unsafe_fn`, `missing_debug_implementations`, and `undocumented_unsafe_blocks`; justify narrow opt-outs (M-STATIC-VERIFICATION).
- When features change, exercise default, no-default, all-feature, and supported feature combinations with `cargo hack`. Validate with the declared MSRV when MSRV-sensitive code or manifests change. Use `cargo audit` for dependency/security work and `cargo udeps` for dependency cleanup.
